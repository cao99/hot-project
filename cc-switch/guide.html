1. 项目概述

1.1 什么是 cc-switch

cc-switch (Cloud Configuration Switcher) 是一个强大的命令行工具，专为管理多云环境配置而设计。它允许开发者和运维人员在不同的云服务提供商配置之间快速切换，极大地简化了多云架构的管理复杂度。

核心价值

在现代云计算环境中，企业和开发团队往往需要在多个云服务商（AWS、Azure、GCP 等）之间进行操作。cc-switch 帮助解决：

  • 配置管理复杂: 不同云服务商的配置文件格式、存储位置各不相同
  • 环境切换繁琐: 手动切换开发、测试、生产环境容易出错
  • 凭证安全风险: 多账号管理增加了凭证泄露的风险
  • 团队协作困难:�队成员可能使用不同的配置，导致环境不一致

1.2 主要功能

多云配置管理

云服务商支持版本配置类型特殊功能
AWS全版本Credentials, Config, CLIIAM Role 切换, MFA 支持
Azure全版本Service Principal, CLITenant 管理, Subscription 切换
GCP全版本Service Account, gcloud configProject 切换, 区域管理
Alibaba Cloud全版本AccessKey, RAM Role资源组管理
Tencent Cloud全版本SecretId/Key, CAM账号体系集成
Custom可扩展自定义配置插件系统支持

环境管理

支持多环境（dev/staging/prod），一键切换，环境隔离，配置继承

凭证管理

系统密钥链加密存储，自动刷新，细粒度权限控制，完整审计日志

CI/CD 集成

Pipeline 友好，环境变量自动注入，无交互模式，Docker 支持

1.3 适用场景

场景一：开发团队的多环境管理

背景: 团队需在 AWS 的 dev/staging/prod 环境间频繁切换。

# 添加三个环境的配置
cc-switch add aws --profile dev --account 123456789012
cc-switch add aws --profile staging --account 234567890123
cc-switch add aws --profile prod --account 345678901234

# 快速切换
cc-switch use aws-dev
cc-switch use aws-staging
cc-switch use aws-prod

场景二：多云架构管理

# 添加多云配置
cc-switch add aws --profile compute
cc-switch add azure --profile database
cc-switch add gcp --profile ml

# 同时激活多个云配置
cc-switch use-group full-stack

场景三：CI/CD 自动化

# GitLab CI 配置示例
deploy:
  stage: deploy
  script:
    - cc-switch use aws-${CI_ENVIRONMENT_NAME} --non-interactive
    - ./deploy.sh

2. 系统架构

2.1 整体架构

cc-switch 采用分层设计，每一层都有明确的职责边界：

┌─────────────────────────────────────────┐
│       CLI Interface Layer               │
│   (commander.js + inquirer.js)          │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│       Configuration Manager             │
│   (YAML Parser + File System)           │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│       Provider Abstraction Layer        │
│   (AWS/Azure/GCP/Custom Providers)      │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│       Security Layer                    │
│   (keytar + encryption)                 │
└─────────────────────────────────────────┘

2.2 配置文件结构

主配置文件位置: ~/.cc-switch/config.yaml

~/.cc-switch/
├── config.yaml           # 主配置文件
├── credentials.enc       # 加密的凭证库
├── profiles/             # 配置文件目录
│   ├── aws-dev.yaml
│   ├── aws-prod.yaml
│   └── azure-prod.yaml
├── cache/                # 缓存目录
├── logs/                 # 日志目录
│   ├── cc-switch.log
│   └── audit.log
├── backups/              # 备份目录
└── plugins/              # 插件目录

2.3 安全架构

凭证采用双层加密存储：

  1. 系统密钥链加密: 使用操作系统提供的密钥链服务（Keychain/Keyring）
  2. 应用层加密: AES-256-GCM 算法二次加密

npm install -g cc-switch

# 输出: cc-switch v1.0.0

npm install -g cc-switch@1.0.0
# 克隆仓库
git clone https://github.com/cloudteam/cc-switch.git
cd cc-switch

# 安装依赖
npm install

# 构建项目
npm run build

# 全局链接
npm link
# 拉取镜像
docker pull cloudteam/cc-switch:latest

# 运行容器
docker run -it --rm \
  -v ~/.cc-switch:/root/.cc-switch \
  -v ~/.aws:/root/.aws \
  cloudteam/cc-switch:latest \
  cc-switch list

# 创建别名以方便使用
alias cc-switch='docker run -it --rm \
  -v ~/.cc-switch:/root/.cc-switch \
  cloudteam/cc-switch:latest cc-switch'
# macOS/Linux
curl -L https://github.com/cloudteam/cc-switch/releases/latest/download/cc-switch-$(uname -s)-$(uname -m) -o /usr/local/bin/cc-switch
chmod +x /usr/local/bin/cc-switch

# Windows (PowerShell)
Invoke-WebRequest -Uri "https://github.com/cloudteam/cc-switch/releases/latest/download/cc-switch-win-amd64.exe" -OutFile "cc-switch.exe"

  before_switch:
    - name: check-mfa
      script: ~/.cc-switch/hooks/check-mfa.sh
      required: true
  after_switch:
    - name: notify-team
      script: ~/.cc-switch/hooks/notify.sh
      async: true

8.3 配置搜索

12. 常见问题

Q: 如何重置主密码？

A: 重置主密码需要重新初始化配置：

rm -rf ~/.cc-switch
cc-switch init

Q: 如何迁移现有 AWS CLI 配置？

A: 使用迁移命令：

cc-switch migrate --from aws-cli

Q: 如何在多台机器间同步配置？

A: 使用云存储同步：

cc-switch sync configure --backend s3 --bucket my-configs
cc-switch sync push
cc-switch sync pull

Q: 如何自定义输出格式？

A: 使用 --format 选项：

cc-switch list --format json
cc-switch list --format yaml
cc-switch list --format table
